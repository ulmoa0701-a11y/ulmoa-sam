# 일단써봄 — 실제 역할별 서비스 오픈 점검 (2026-10-14)

## 최종 판단
**배포/실사용 승인: 보류.** 현재 GitHub Pages `test/ildan-sseobom/design-v15/`는 실제 계정이 없는 가상 시연판입니다. Netlify `ulmoa-ildan-secure-test` 사이트는 외부에서 루트와 `/api/health`가 404이고, 사이트 전용 환경변수 목록이 비어 있습니다. 접속이 된다는 것만으로 실제 아동 상담정보를 입력할 수 있는 것은 아닙니다.

## 구현된 개발 코드
- 서버 패스키 인증 WebAuthn, 역할 기반 서버 접근, 관리자가 치료사를 초대하고 치료사가 학생/보호자를 초대하는 절차
- 학생 자기 기록만 읽기, 보호자 본인 작성 기록만 읽기, 치료사는 자신에게 배정된 학생의 **명시적으로 공유된 항목만** 조회
- 학생·보호자 간편/자세히, 선택형 ABC(행동 관찰과 사전/사후 맥락), 학생 감정 선택
- 실제 DB용 AES-256-GCM 암호화 저장, 공유취소 시 서버 공유 키 제거, Google Drive 새 연결·백업은 승인 전 기본 차단
- 합성 데이터 Node 보안/통합 검사 및 Chrome 데스크톱/모바일 가상 테스트 통과

## 실사용 전 필수 작업 — 순서대로
1. Netlify 프로젝트 `ulmoa-ildan-secure-test`를 소유한 계정에서 사이트의 GitHub 소스를 저장소 `ulmoa0701-a11y/ulmoa-sam`에 연결하고 **보안 개발 브랜치 `feature/ildan-secure-auth-20261010`** 를 배포 대상으로 지정. Base directory `secure-portal`, publish `public`, functions `netlify/functions`. 기본 `main`에는 공개 가상 시연판만 있습니다. 임의로 GitHub Pages를 보안 로그인으로 전환하지 말 것.
2. Netlify Database(Postgres)를 해당 사이트에서 활성화하고 `@netlify/database` 및 관련 npm 의존성 설치/마이그레이션 자동 적용 확인. **무료 요금·제한을 먼저 확인하고, 동의 없이 유료 플랜/결제에 가입하지 말 것.**
3. Functions 전용 환경변수 `APP_ORIGIN`(정확한 HTTPS 공개 도메인), `RECORD_ENCRYPTION_KEY`(암호학적 안전 난수 32바이트 base64), `INITIAL_ADMIN_SETUP_TOKEN`(충분히 긴 난수) 생성·설정. 비밀키는 GitHub 소스, HTML, 채팅 화면에 게시하지 않음. 암호화키 분실 시 기존 기록 복구 불가능: 안전한 관리자 보관 계획 필요.
4. 실서비스 도메인에서 `node tests/live-deploy-check.mjs https://...netlify.app`를 실행하고 6/6 통과할 것. 실패 시 실제 사용자 정보 입력 금지.
5. Netlify 사이트 접근 정책에 현재 **팀 SSO 강제 설정이 존재**합니다. 학생·보호자가 조직 SSO 계정을 갖지 않았으면 로그인 화면이 열리지 않습니다. **안전한 서버 인증, DB, 권한 검증이 완료되기 전 SSO를 해제하지 말 것.** 실제 로그인 접근을 대외 공개할 때에만 적절한 접근 정책으로 변경.
6. 실제 테스트 계정(실명/건강정보 없는 가상 4명): 관리자 → 치료사 초대 → 치료사 패스키 등록 → 학생 초대/패스키 등록 → 해당 학생 보호자 초대/패스키 등록. 각각 다른 브라우저/장치로 로그인해야 하며 다른 역할로 페이지를 강제로 열었을 때 서버에서 403/차단인지 확인. 관리자나 보호자가 학생의 비공개 원문을 읽을 수 없어야 합니다.
7. 학생·보호자의 비공개 기록이 치료사 계정에서 보이지 않는지, 명시적 항목 선택한 뒤 해당 필드만 읽히는지, 공유 철회 즉시 읽을 수 없게 되는지 **실제 DB 트랜잭션·재로그인·기기 전환 상태에서** 확인. ID를 조작한 다른 학생/보호자/치료사가 기록을 열 수 없어야 합니다.
8. 아동/법정대리인에게 기록 목적·공유 상대·보존기간·철회·삭제·권리 안내 및 동의 절차 마련. 교사/센터 운영자가 등록 사용자의 건강·상담 데이터를 수집할 법적 근거·위탁 및 보안/감사 체계 검토. **일기 작성 자체는 의무가 아님**; 틱/강박에 대한 일상적 관찰·횟수 세기 강요 금지.
9. 삭제·보존/백업 복구·키 순환·유출시 대응·계정 분실/관리자 계정 복구 점검. Google Drive 복사본 삭제, OAuth 실제 계정 및 멀티사용자 경쟁상태 검증 없이 `DRIVE_BACKUP_ENABLED`를 켜지 말 것.

## 내일 수업에서 가능한 것
개인정보 없는 **가상 인물·가상 상황**으로 기록 화면과 ABC 기능을 시범 사용하거나 보호자에게 빈 양식 구조를 설명하는 것까지 가능합니다. 실명을 가린다고 해도 진단/치료 내용으로 재식별할 수 있으면 안전한 가상자료가 아닙니다. 실제 상담 기록은 기존 기관의 승인된 보관 방식으로 작성하세요.

## 자동 검증과 실사용의 구분
GitHub Actions 단위·모의 테스트 = 코드 품질 검증. 실환경 패스키 + 개인정보 저장/권한/복구/철회 + 법적 요건 + 사용자 부담 검토 = **별도의 필수 승인 단계**입니다. 자동 검사 성공 또는 Netlify URL 200만으로 실사용 승인하지 않습니다.
