# 일단써봄 — 역할별 기록 보호 + 통합 패스키 로그인 (개발 중)

**상태(2026-10-10): GitHub 개발 브랜치에 코드만 작성한 상태. 실제 서버·DB·Google OAuth 연동 및 실기기 패스키 테스트가 완료되지 않았습니다. 실제 아동 상담정보를 입력하지 마세요.**

## 사용 방식

학생·학부모·치료사·관리자는 모두 **같은 패스키 로그인 버튼**을 사용합니다. 처음 계정을 만들 때 닉네임과 담당 치료사 초대코드를 입력하고 기기의 패스키를 등록합니다. 이후에는 로그인 버튼 → 기기 자체의 지문·얼굴·기기 잠금 PIN 등으로 본인 확인을 합니다. 서버는 얼굴 이미지·지문 정보를 받거나 보관하지 않습니다. 4자리 앱 비밀번호는 없습니다. 실제 기기 PIN 자릿수/수단은 운영체제 설정에 따릅니다.

복구: 기기를 분실하면 담당 치료사가 대면 등 신원 확인 후 30분 유효 재등록 코드를 발급합니다. 학생·학부모는 같은 재등록 화면에서 패스키를 새로 등록합니다. 분실 시 이전 패스키·세션은 폐기됩니다. 치료사는 관리자에게 복구를 요청합니다. **관리자 단일 패스키 분실 복구는 미구현**이므로 운영 전 추가 수단과 복구 절차를 설계해야 합니다.

## 권한

학생은 자기 기록만 열람하고 개별 기록 공유 여부를 선택합니다. 학부모는 학부모 본인이 쓴 관찰·전달사항만 열람할 수 있고, 학생의 비공개 기록은 볼 수 없습니다. 담당 치료사는 배정된 학생의 명시적으로 공유된 기록만 열람할 수 있습니다. 관리자는 치료사 초대 기능만 있으며 기록 열람 기능은 없습니다. 접근은 반드시 서버에서 검증합니다.

## 보안 코드

- `@simplewebauthn/server`로 실제 WebAuthn challenge 등록·서명 검증 코드를 작성했습니다. 패스키 등록은 discoverable credential 및 사용자 확인 필수입니다.
- 초대코드/재등록 코드/인증 challenge는 임의 생성·일회용·만료·DB 검사. POST 요청은 Origin 검사를 거칩니다.
- 서버 발급 세션(HTTPOnly, Secure, SameSite)과 서버 측 RBAC; 기록 데이터는 AES-256-GCM 암호화.
- 백엔드가 실제 DB 연결에 성공하고, 인증 라이브러리를 설치하고, HTTPS `APP_ORIGIN` 및 서버 비밀값을 설정해야만 작동합니다.
- 초기 코드의 scrypt 비밀번호 함수는 호환성 테스트 파일에 남아 있으나 새 패스키 UI와 API는 비밀번호 로그인을 제공하지 않습니다.
- 이 코드는 개인정보 처리방침, 동의, 법정대리인 동의, 보존기간/삭제 정책, 운영자 감사로그, 법적·보안 적합성 검증을 대체하지 않습니다.

## 미완료 / 실환경 배포

1. 기존 GitHub Pages `/test/ildan-sseobom/`는 계속 **공개 시연본**이며 이 서버형 프로그램과 연결되어 있지 않습니다.
2. Netlify의 별도 `ulmoa-ildan-secure-test` 프로젝트를 GitHub 개발 브랜치의 `secure-portal` 베이스 디렉터리에 연결해야 합니다. 현재 배포되지 않았습니다.
3. Netlify Database/Postgres 지원 및 가격·개인정보 처리 조건 확인, 2개 SQL migration 적용 검증이 필요합니다. `package.json`의 `@netlify/database`, `@simplewebauthn/server`를 설치해야 합니다.
4. Functions 환경변수: `APP_ORIGIN`(정확한 HTTPS 도메인), `RECORD_ENCRYPTION_KEY`(무작위 32바이트 base64), `INITIAL_ADMIN_SETUP_TOKEN`(무작위 32바이트 이상). 값들은 GitHub에 업로드하지 않습니다. 예전 AUTH_PEPPER는 패스키용에 필요하지 않습니다.
5. 초기 관리자 등록 → 관리자 치료사 초대 → 치료사 가입 → 학생 초대 → 학생 등록 → 학부모 초대 → 학부모 가입 순으로 실제 서버/DB 테스트를 거쳐야 합니다. 반드시 다른 계정에서 비공개기록 접근 차단을 검증해야 합니다.
6. 담당 치료사마다 자신의 Google OAuth 계정을 직접 승인해야 하며, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`(서버 전용), `APP_ORIGIN`이 있어야 합니다. 승인 후 **담당 치료사 드라이브에만** 공유 기록이 들어가는지 실측해야 합니다. 아직 승인·업로드 테스트를 하지 않았습니다.
7. 의료·상담정보를 저장할 서비스이므로 보안 감사, 동의·삭제·복구·감사로그·기기 분실 및 계정 복구 정책이 마련되기 전 실사용 금지.

## 테스트 및 한계

`node --check netlify/functions/api.mjs`, `node --check public/app.js`, `node --test tests/security.test.mjs` 등 로컬 구문·기존 접근제어 테스트 수행 가능.

WebAuthn 암호학적 등록·서명 검증은 실제 HTTPS 앱에서 패스키 생성 후 실기기 통합 테스트가 필요합니다. npm 패키지 설치 및 Netlify DB 연결이 이 환경에서 완료되지 않아 서버 인증 전체의 성공을 확인했다고 주장하지 않습니다. 또한 앱 자체는 전문 치료의 대체제가 아닙니다.
