# 일단써봄 — 계정·담당 치료사별 기록 접근 제어 (서버형 개발본)

**상태: 소스 구현 + 독립 단위/모의 UI 테스트 완료. 실제 Netlify 서버·DB·Google OAuth 배포/통합 테스트 전. 실제 학생 상담정보 사용 금지.**

기존 공개 홈페이지의 `/test/ildan-sseobom/`는 **시연용 HTML**이며 이 프로그램의 인증 기능과 무관합니다. 이 프로젝트를 GitHub Pages에 파일로만 올리면 로그인·기록 저장 기능이 동작하지 않습니다. 서버로 실행해야 합니다.

## 역할·권한

- **학생:** 초대코드·담당 치료사 선택 후 닉네임과 8자리 이상 비밀번호로 가입. 작성자는 본인 기록만 조회. 개인 기록은 기본 비공개. 명시적으로 선택한 공유기록만 담당 치료사가 열람.
- **학부모:** 담당 치료사가 지정한 학생에 연결해 초대. 본인이 쓴 관찰·전달사항만 조회. 공유를 체크한 기록만 치료사에게 노출. 아동 개인 기록은 볼 수 없음.
- **치료사:** 관리자가 발급한 초대코드로 가입, 12자리 이상 비밀번호. **자신에게 배정된 학생의 명시적으로 공유된 기록만** 열람·CSV 다운로드. 학생·학부모의 비공개 기록이나 다른 담당 치료사 기록은 불가.
- **관리자:** 치료사 가입 초대, 복구 계정 관리. 기록 내용 열람 API 없음.
- **Google Drive:** 학생의 Google 계정이 아닌, **담당 치료사 본인이 OAuth를 통해 승인한 계정**에 전용 비공개 폴더 생성. 공유 기록은 가능하면 바로 동기화, 실패하면 서버 DB에 남겨 두고 치료사 화면에서 재시도. `drive.file` 최소 권한 범위 사용.

## 보안

- 닉네임은 인증 정보가 아니며, 비밀번호 확인은 서버에서만 처리.
- 비밀번호: 고유 솔트 + scrypt + 서버 전용 pepper. 최소 학생/학부모 8자리, 치료사/관리자 12자리. 틀린 로그인 5회시 15분 잠금.
- 최초 가입은 치료사별/관리자별 7일 유효, 1회용 192비트 초대코드. 닉네임이나 담당자 변경으로 타 계정 접근 불가.
- 비밀번호 분실 시 관리 권한자가 대상자를 별도 확인 후 30분 유효 1회용 재설정 코드 발급, 기존 로그인 세션 무효화.
- 서버 발급 무작위 세션, HttpOnly+Secure+SameSite=Lax 쿠키. Lax는 구글 로그인 콜백을 위해 사용. 변경 요청에는 동형 출처 Origin 검증, JSON 전용, 요청 크기 제한.
- 기록은 서버에서 AES-256-GCM 암호화해 DB 저장. 조회 시 작성자/담당자/공유 여부를 서버에서 다시 검사.
- 프런트엔드는 서버에서 받은 권한만 표시; 브라우저 저장소에 인증 토큰/민감 기록을 저장하지 않음.
- **구글 드라이브로 복사된 기록은 본인 Google 계정의 원본 폴더에 별도로 남음.** 공유를 선택하기 전 명시적으로 고지해야 함.
- 앱 수준 암호화/인증은 의료정보 개인정보 보호 법규 준수를 자동으로 보증하지 않음. 실사용 전 기관 동의, 위탁계약, 저장지역/보존기간, 접근기록·삭제 정책, 백업·복구, 사고 대응 검토가 필요.

## 배포 준비: Netlify (AppDeploy 사용하지 않음)

1. `ulmoa-sam` GitHub 저장소의 별도 개발 브랜치에서 `secure-portal` 하위 폴더를 Netlify의 **base directory**로 설정해 새 Netlify 프로젝트에 Git 연결. 기존 GitHub Pages 게시물은 그대로 유지.
2. Build command: `npm install` (또는 Netlify 자동 설치 후 `echo build`), publish directory: `public`. `netlify.toml`의 `functions` 디렉터리와 `netlify/database/migrations`가 모두 배포에 포함되는지 확인. Node 20.12 이상.
3. Netlify에서 `@netlify/database` 지원/요금·지역을 확인. 배포 시 SQL 마이그레이션 성공 및 데이터베이스 생성 확인. 사용량에 따라 비용이 발생할 수 있어 무료 사용 보장은 하지 않음.
4. Netlify Functions 범위의 환경변수 등록 (레포·브라우저 코드에 절대 넣지 말 것):
   - `RECORD_ENCRYPTION_KEY` — 임의 32바이트의 base64 (예: `node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"`)
   - `AUTH_PEPPER` — 임의 32바이트 이상의 고유 문자열
   - `INITIAL_ADMIN_SETUP_TOKEN` — 임의 32바이트 이상의 복잡한 관리자 설치 토큰
   - 선택 Google OAuth용 `APP_ORIGIN` — Netlify 앱의 정확한 `https://...netlify.app` 주소
   - 선택 Google OAuth용 `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` — Google Cloud OAuth 웹 클라이언트 자격증명. 리디렉션 URL: `${APP_ORIGIN}/api/drive/callback`. OAuth 동의 화면 구성/사용자 추가 필요.
5. 재배포, `/api/health` 정상 응답 확인. 최초 관리자 계정은 화면의 '관리자 최초 설정'에서 설정코드 입력. 최초 관리자가 만들어진 후 재설정코드 환경변수 제거 가능.
6. 관리자 → 치료사 초대 → 치료사 회원가입 → 치료사 학생 초대 → 학생 가입 시 해당 치료사 선택 → 학부모 초대(학생 연결) → 학부모 가입 → 양쪽 기록/공유/조회/기록 비공개/타 계정 접근 차단 검증.
7. 구글 OAuth 활성화 후 **치료사별로 각자 로그인**해 드라이브 승인. 테스트용 가상기록 1건을 공유하고 교사 본인 구글 폴더에서 파일 확인. 다른 치료사 폴더에 나타나지 않는지 확인.
8. 테스트 승인 후에만 일단 해봄노트 '테스트' 카테고리의 링크를 배포된 안전한 앱 주소로 변경. 기존 공개 시연본은 실사용 링크로 쓰지 않음.

### 구글 관련 주의

Google Cloud OAuth 앱 구성과 각 치료사의 Google 계정 승인 과정은 이 소스 코드에 포함되지 않고 **실제 계정 소유자의 동의**가 필요합니다. `GOOGLE_CLIENT_SECRET` 및 비밀번호를 채팅·GitHub 저장소에 붙이지 마세요. OAuth 승인/사용 정책에 따라 추가 검증이 필요할 수 있습니다.

## 로컬 테스트

```sh
npm install
npm test
node --check netlify/functions/api.mjs
python tests/ui_smoke.py       # Playwright와 Chromium이 있으면 모의 API로 화면 검증
```

본 환경에서는 `npm` 패키지 저장소로의 네트워크 접속이 불가능하여 **실제 Netlify DB 연동/서버 통합 테스트는 실행하지 않았습니다**. 보안 함수 단위 테스트 및 모의 API UI 테스트는 완료됐습니다.

## 기능 범위/미완료 점

- 완료 (소스 기준): 닉네임 회원가입·로그인·로그아웃·서버 쿠키 세션·초대코드·로그인 실패 잠금·암호화 기록 저장·개인/공유 분리·담당 치료사 확인·학부모 전달사항·CSV·일회용 비밀번호 재설정·구글 OAuth/백업 코드·기존 목적인 짧은 기록/상황 연습/별도 코딩 활동.
- 미완료 (실환경 기준): 실제 Netlify 프로젝트 연결, DB 마이그레이션/계정별 REST API QA, Google OAuth 승인/각 치료사 드라이브에 업로드된 결과 검증, 삭제·보존기간·감사로그·기관 운영 보안 승인.
- 이 앱 자체는 강박 치료 효과가 검증된 의료 소프트웨어가 아니며 ERP 등 전문 치료를 대체하지 않음.
