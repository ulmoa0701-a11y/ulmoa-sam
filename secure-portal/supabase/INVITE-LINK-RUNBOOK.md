# 일단써봄 · 카카오톡/브라우저 공용 역할별 초대 링크 (2026-10-15)

## 실제 반영한 기능
- 치료사가 학생 또는 보호자를 선택한 뒤 **랜덤 64자리 단회 초대코드**를 링크로 만들어 카카오톡 등으로 보냅니다.
- 주소는 `https://.../supabase-staging/#invite=<code>` 형태로, 토큰은 **URL fragment**에 있어 브라우저 첫 페이지 GET 및 대부분의 서버 접속 로그에 전송되지 않습니다. 발급받은 사람이 링크를 유출하면 타인이 이용할 수 있으므로 비밀로 전달해야 합니다.
- 최초 링크 열기는 `POST /invite-preview`로 서버가 등록 대상 역할과 만료를 조회하지만 **초대코드를 사용하지 않습니다**. 미리보기 링크 크롤러 또는 카카오톡 내장 브라우저에서 열었다가 기본 브라우저로 옮겨도 코드가 살아 있습니다.
- 실제 최초 등록은 명시적으로 `기기 등록하고 시작`을 누를 때만 시도합니다. 48시간 만료·단회 등록·학생/보호자 고정 역할은 SQL에서 강제합니다.
- `POST /invite-register`는 서버의 `INVITE_REGISTRATION_ENABLED=true`라는 **명시적 승인** 전에는 **항상 503**을 반환합니다. 현재는 비활성 상태입니다.
- 최초 등록 방안(검증 전): 링크 소지자가 등록을 승인하면 서버가 무작위 내부 계정(실제 이메일 불필요)을 만들고 초대코드를 원자적으로 사용 처리하며, 1회 로그인 응답을 거쳐 **기기 패스키**를 등록합니다. 이후에는 닉네임이나 이메일 없이 기기 인증을 이용합니다.
- 미지원 카카오톡 내장 브라우저를 위해 **링크 복사** 기능과 크롬·삼성 인터넷·사파리로 열기 안내를 제공했습니다.
- 클라이언트는 `@supabase/supabase-js` **v2.105.0 이상**에서 실험적 패스키 API `registerPasskey/signInWithPasskey`를 사용합니다.
- 학생의 개인 기록과 보호자가 작성한 기록은 SQL과 Edge에서 별도로 접근을 제한하며, 치료사는 별도로 동의한 공유 기록만 조회하도록 유지합니다.

1. Supabase 대시보드 → Authentication → Passkeys에서 활성화. Relying Party ID는 **ulmoa0701-a11y.github.io**, 허용 Origin은 **https://ulmoa0701-a11y.github.io**. 이는 **실험적 기능**으로 실제 Android/Apple/카카오톡 내장 브라우저에서 검증할 것. 향후 자체 도메인으로 옮기면 패스키가 무효화될 수 있으므로 도메인 정책 선결.
2. 치료사 최초 계정은 본인 확인한 운영자가 기존 Supabase Auth 이메일 OTP로 로그인한 뒤 **인증된 UUID를 신원 확인 후 수동으로 치료사 역할 등록**해야 함. 현재 학생·보호자에게 이메일 계정을 만들거나 제출하도록 요구하지 않음.

5. 강력한 암호화키, 보존기간/삭제·내보내기, 초대 취소, 감사기록, 세션/신원 복구, 실제 권한 차단·교차 로그인/모바일 브라우저 테스트 완료 이전까지 `CLINICAL_WRITES_ENABLED` 활성화 금지. **지금은 실제 상담정보 입력 금지**.
6. 링크만 받으면 영구 열람되는 방식이 아님. 카카오톡 내장 브라우저와 크롬의 저장된 로그인은 분리되며, 이후 브라우저 전환은 **등록된 패스키** 또는 치료사 신원 확인 후 재등록으로 처리해야 함.
