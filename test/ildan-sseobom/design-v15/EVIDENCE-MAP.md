# 일단써봄 v15 — 근거-기능 대조표 / 임상 설계 검토

작성 기준: 2026-10-12. 이 문서는 **연구가 검증한 치료법**과 **그 연구에서 착안한 도구의 UI 설계 가정**을 구별한다. 실제 아동 상담 기록은 공개 GitHub 저장소나 공개 체험판에 입력하지 않는다.

## 1. 가장 중요한 결론

- 일단써봄은 **검증된 CBT, ERP, CBIT, 행동기능평가, 표준화 척도**가 아니다.
- 임상적으로 근거가 있는 특정 요소(가족을 포함한 맥락적 평가, 자발성, 관찰 사실과 추론 구분, 치료사 주도 개입)를 반영한 **자체 설계 기록·상담 보조 도구**다.
- v15에 대해 효과 크기, 민감도/특이도, 검사-재검사 신뢰도, 치료 성과, 유해사례 비율을 산출한 연구가 없으므로 **임상적 무해성·치료 효과·진단 정확도를 주장하지 않는다**.
- 현 배포는 모의 로그인 및 모의 저장을 이용하는 데모이며 **실제 개인건강·상담 정보를 입력하지 않는다**.

## 2. 연구 → 구성요소 연결과 근거의 범위

| 연구·가이드라인 | 실제 뒷받침하는 내용 | 적용한 화면/필드 | 적용의 한계와 판정 |
|---|---|---|---|
| NICE CG31 §1.5.1.9, §1.5.2.12: 아동·청소년 OCD에 발달 수준을 고려하고 가족이 참여하는 CBT(ERP 포함), 협력적 목표 설정 | 치료는 치료적 관계와 전문적 평가·협력적 계획에 기반해야 함 | 학생: 자발적 자유 기록, 공유 선택. 치료사: 다음 회기 합의한 계획; ERP 평가·계획 란 접힘 | **강한 치료 지침 → 앱 설계 원칙 간접적 참고**. 일기장이 ERP 치료인 것은 아님 |
| Andrén et al. ESSTS 2022, doi:10.1007/s00787-021-01845-z: HRT/CBIT 근거 | 틱 중재에서 HRT/CBIT가 근거가 있음. 단독 자기관찰만으로 동등한 치료효과는 입증되지 않음 | 학생: 틱/반복경험 기록은 선택·기본 접힘. 치료사: CBIT 검토는 별도의 전문가용란 | **CBIT 치료 근거를 학생 일기 기록의 효과로 전용하지 않음** |
| Lebowitz & Bloch (2012), doi:10.1586/ern.11.200: 아동 OCD에서 가족 수용행동의 중요성과 연관성 | 부모·가족의 반응도 함께 평가할 이유가 있음 | 보호자: 당시 상황/주변 반응/이후 영향의 선택형 관찰; 치료사: familyResponse | **부모의 행동을 단일 사례로 '잘못된 수용행동'이라고 분류하지 않음**. FAS 같은 검사를 대체하지 않음 |
| US Department of Education (2024), *Using Functional Behavioral Assessments to Create Supportive Learning Environments*: 관련 맥락의 다양한 자료 수집과 기능적 가설 | 관찰 출처, 전후 상황과 행동의 구분 및 단정 금지 | 보호자: observation, origin, context, childWords, response, after, impact. 치료사: 가설·다른 설명·불확실성 | **ABC식 관찰 정보이지, 기능적 행동평가(FBA) 완료가 아님**. 횟수·선행원인 분석 자동화 금지 |
| Henry et al. (2026), doi:10.1038/s44277-026-00058-z: 청소년 정신건강 EMA 130연구/14,400명 메타분석 | 반복 질문의 부담과 준수율 변동을 무시하면 안 됨. 연구 프로토콜의 참여도에 관한 자료 | 학생: 필수 일일 체크·연속일·알림 없음, 간편 입력. 치료사: burdenReview | **EMA는 이 도구처럼 자유롭게 쓰는 일기와 다르며, '무조건 자발적 기록이 효과적'이라는 근거는 아님** |
| WCAG 2.2, W3C | 입력 가독성·키보드 조작성·명확한 레이블 등 접근성 점검 원칙 | 공통: 버튼·입력 텍스트/레이블, 모바일 브라우저 UI, 청각 안내 의존 최소화 | **기능 테스트 통과 ≠ WCAG 적합성 인증/실기기 접근성 평가 완료** |

## 3. 각 역할에 실제 적용한 점

### 학생

- 메인: 자유 글쓰기. **최소한의 표현만 남겨도 됨**. 실제 문제나 불안을 매번 분석하도록 하지 않음.
- 자세히 기록: 감정, 컨디션, 신체 감각/움직임, 경험 영향, 생각 등은 접힌 선택 항목.
- 기록 빈도·횟수 카운터·연속 기록 배지·진단 결과·자동 해석 없음.
- **임상적 가정**: ADHD/완벽주의 성향이 있는 학생에게 자유·간편 입력이 부담을 낮출 수 있다. 이 학생에서 직접 검증된 것은 아님.
- **관찰할 부작용**: 내용 확인, 문장 수정, 감정/틱 스캔, 안심 확인 요구, 수면 전 기록 지연, 가족 갈등.

### 보호자

- 기본: 관찰 날짜(작성 시각과 별도), 관찰 사실 1칸, 정보 출처 **선택**.
- 자세히(접기): 그전·당시 상황, 아이가 직접 한 표현(정확히 기억나는 경우만), 주변 사람의 반응, 이후 진행, 생활 변화, 치료사 전달사항.
- 가족 수용행동이나 강박/틱의 원인을 **자동 판단하지 않음**. 특정 증상을 일부러 찾거나 횟수를 세게 하지 않음.
- 출처를 선택하지 않더라도 작성 가능. 아이의 실제 말과 보호자의 해석은 별개로 표시.
- **임상적 가정**: 발언 원문과 간접 전달을 구분하면 치료사의 확인 질문에 유용할 수 있다. 양식 자체의 예측타당도 미검증.

### 치료사

- 기본 메모: 학생의 직접 발언 / 보호자가 전한 이야기 / 직접 확인한 관찰 / 학생과 합의한 다음 계획.
- 선택형 사례개념화: 기능 영향, 가족 반응, 잠정 가설, 다른 설명 가능성, 미확인 내용, 기록 사용의 불편/반복 확인 여부.
- ERP/CBIT: **훈련된 전문가만 실제 평가 결과에 근거해 검토**. 가상의 상황이나 선택항목 값으로 과제를 자동 생성하지 않음.
- 학생·보호자의 **공유한 내용만 참고**. 미공유 정보에 대한 접근 권한이 없다는 운영 원칙을 명시.
- YGTSS, PUTS, CY-BOCS, FAS는 **전문가가 적응증·검사법을 확인해 별도 평가**하는 도구로 취급하며, 앱의 자기보고 필드에 임의로 점수화를 붙이지 않음.

## 4. 실제 사용 전 검증해야 하는 가설

| 가설 | 테스트 방식 | 통과의 의미 |
|---|---|---|
| 기록이 부담을 늘리지 않는가 | 학생에게 사용 선택권 설명, 주 1회 면담에서 부담·수정/재확인·수면 영향 질문 | 초기 수용성만 평가. 임상적으로 무해함을 증명하지 않음 |
| 학생이 원하는 표현을 남길 수 있는가 | 가상 데이터 입력, 1–2문장 기록·기록 생략·기록 후 미공유 성공 확인 | 사용성 확인. 치료 효과가 아님 |
| 보호자가 관찰 사실과 해석을 구분할 수 있는가 | 가상의 상황 3건을 읽고 observation/origin/childWords를 작성하게 한 뒤 독립 판정 | 기록 이해도 확인. 관찰자간 신뢰도 연구가 아님 |
| 치료사가 정보 출처와 가설을 혼동하지 않는가 | 학생·보호자 기록이 상충하는 합성 사례를 넣고 상담 메모 검토 | 역할별 사용성 확인. 감별진단 정확도 아님 |
| 접근·저장·동의가 실제 보장되는가 | 서버/DB/인증/삭제/백업 포함 별도 보안 감사와 실제 권한 침해 시험 | 운영 선결 조건. 현재 미통과 |

## 5. 아직 빠진 필수 연구 및 운영 준비

1. 관련 전문가에 의한 콘텐츠 타당도 점검(문항·용어·질문이 과도한 증상 주시를 유도하는지).
2. 학생 및 보호자와의 사용성 면담, 특히 기록 생략/공유거절/중단이 실제로 부담 없이 가능한지.
3. 불안·강박·틱·ADHD가 함께 나타나는 상황에서 증상별로 **기록 적합성**이 다른지 검토.
4. 인공와우 사용자 관점에서 알림음 없는 텍스트 UI·정보 전달 접근성 검토.
5. 실제 자료 취급 전 개인정보 법적·기술적 적합성, 민감정보 취급 동의·삭제·복구, 제3자 저장 경로 검증.
