# 도토리 배달 대작전 — mission-v4 자산 스타일 가이드

작성일: 2026-10-22 · 작성: Claude (작업지시서 기반)

## 스타일 앵커

- **확정 스타일**: "cute 3D clay toy" — 부드러운 매트 재질, 파스텔 톤, 스튜디오 소프트 라이팅, 둥근 실루엣, 투명 배경.
- 이 스타일은 `ulmoa-center-os` 저장소의 "울모아 생각놀이터" 아이콘 세트(모아의 숫자 숲과는 다른 자매 프로젝트)와 같은 계열이며, 사용자가 이번 작업에서 명시적으로 "생각놀이터 아이콘 그림체처럼" 만들어 달라고 지정했다.
- 사용자가 1차 체크포인트(나무·도토리·바구니·곰)를 승인한 뒤 "나머지들 싹다 만들어"라고 지시해, 실제 코드에서 쓰이는 나머지 동물(rabbit/fox/frog/bird — 작업지시서의 2차 목록에 있던 squirrel은 실제 코드에 쓰이지 않아 제외)과 접시(plate)까지 전부 같은 스타일로 확장했다.
- 숲 배경(`forest-world.svg`)은 이번에도 변경하지 않았다 — 평면 벡터 일러스트 배경 위에 글로시 3D 클레이 오브젝트가 올라가는 형태라, 색감은 부딪히지 않지만 기법 자체는 완전히 통일되지 않았다. 다음 단계로 분리해 두었다(asset-manifest.json `notDone` 참고).

## 제작 경로 (중요 — 예외 승인 기록)

- `CLAUDE.md`와 이번 작업지시서 둘 다 원칙적으로 Canva 사용을 금지한다.
- 1차 벡터(SVG) 시안을 `forest-world.svg`와 동일한 손그림 기법으로 먼저 제작했으나, 사용자가 대화 중 "생각놀이터 아이콘 그림체(클레이 스타일)로 맞춰 달라"고 명시적으로 요청했고, 이는 Canva로만 재현 가능한 스타일이어서 사용자에게 재확인했다.
- 사용자가 **"이번 작업은 Canva 써도 됨 (예외 승인)"**을 명시적으로 선택했다 (AskUserQuestion 응답, 2026-10-22).
- 따라서 이번 mission-v4 자산은 `mcp__Canva__generate-image` + `remove-background`로 제작했다. **이 예외는 이번 작업물에 한정되며, 저장소의 기본 Canva 금지 규칙을 변경하지 않는다.**

## 색/광원/시점

- 광원: 좌상단 소프트 스튜디오 라이트, 부드러운 드롭섀도.
- 재질: 매트 클레이(비반사), 둥근 모서리.
- 팔레트: 도토리 — 갈색/크림(#946239 계열), 나무 — 파스텔 그린 캐노피 + 갈색 줄기, 바구니 — 라탄 베이지/브라운, 곰 — 밝은 브라운 털 + 크림 배.
- 배경: 모든 오브젝트/캐릭터는 투명 배경(배경 제거 완료).

## 수량 표현 방식 (코드 구현)

- 개별 파일을 무수히 만들지 않고, 기본 오브젝트(나무/바구니/도토리 1개) + CSS 포지셔닝으로 0~N개 수량을 조합한다.
- "숲속 나무" 칸: `acorn_tree.png`를 배경으로 깔고, 남은 도토리 수만큼 `acorn_single.png` 칩을 나무 밑동 쪽에 띄운다 (실제 가지 좌표에 정밀히 박아 넣지 않음 — 가지별 좌표 고정은 2차 확장 과제로 남김).
- "내 배달 바구니" 칸: `basket_empty.png`를 배경으로 깔고, 담은 도토리 수만큼 `acorn_single.png` 칩을 바구니 입구(손잡이 아래, 테두리 라인) 위치에 쌓는다. 실제 테두리 좌표는 PC 1280px 화면에서 픽셀 단위로 보정했다.
- 검증: 현재 콘텐츠의 실제 최대 수량(공유 미션 기준 4개)까지 PC·모바일에서 확인함. 10개까지는 아직 실제 콘텐츠에 없어 미검증 (아래 "미완료" 참고).

## 곰 표정 상태

- `bear_waiting.png`: 기본 대기 표정 — 환영 카드, 친구 대기 화면에 사용.
- `bear_happy.png`: 성공 시 양팔을 들고 웃는 표정 — 배달 성공(success) 화면에서만 사용.

## 3차 업데이트 — 배경 결정 + 구조(오버월드) 재설계 (2026-10-22, 같은 날)

### 배경: 클레이 스타일로 교체 확정

- `forest_background_clay.png`를 생성해 `.stage` 배경(`forest-world.svg` 자리)에 적용하고 PC 1280 / 태블릿 / 모바일에서 비교했다.
- 원본 생성 해상도가 199×112로 낮아 데스크톱에서 흐려 보일 위험을 우려했으나, 실제 UI(지도 화면·이동 화면) 위에 얹어 놓고 보니 전경의 글로시 클레이 오브젝트와 그림체가 일치해 훨씬 자연스럽고, 흐림도 실사용 화면에서는 크게 거슬리지 않았다 (`previews/overworld_map_pc.png`, `previews/travel_beat_pc.png` 참고). 기본값으로 채택한다 — 1차 리포트에서 "사용자 결정 필요"로 남겨뒀던 항목을 이번에 해소.

### 구조 재설계: 왜, 그리고 무엇을

사용자가 1~2차 결과물을 보고 "학습지 구조 아니냐, 길 가다 나무 발견하고 그런 스토리도 없고 그냥 문제 풀듯 하지 않냐"고 직접 지적했다. 맞는 지적이었다 — 1~2차는 자산 교체 + 애니메이션 양념이었을 뿐, `mission.js`의 흐름 자체는 카드가 바로 다음 카드로 바뀌는 학습지식 `scene()` 전환 그대로였다.

사용자에게 범위를 확인(AskUserQuestion)했고, "전체 구조 재설계(오버월드/맵)"를 선택했다. 적용한 것:

- **숲속 지도(오버월드) 화면**: `CONCEPTS` 배열에 이미 존재했지만 화면에 전혀 쓰이지 않던 시적인 이름(`첫 번째 숲길`/`두 번째 숲길`/`세 번째 숲길`과 설명)을 실제로 지도 노드로 보여준다. 잠김/현재/완료 상태를 시각적으로 구분하고, 완료 노드는 체크 배지가 붙는다.
- **이동(travel) 비트**: 각 숲길의 시범(demo) 직후, 실제 과제로 들어가기 전에 "오솔길을 따라 걷다 보니 배고픈 친구들이 나무 아래 모여 있어요!" 같은 한 줄 발견 서사 + 걷는 느낌의 점 애니메이션을 끼워 넣는다. 매 스텝마다는 아니고 챕터당 1회 — 반복으로 지루해지는 것을 피하기 위한 의도적 범위 제한.
- 지도 노드 아이콘: `share`→`acorn_tree.png`(기존 재사용), `compare`→`map/path_fork.png`(신규 생성, "두 갈래 오솔길" 컨셉과 일치), `make`→`reward_flower.png`(기존 재사용, 챕터 완료 축하 연출과 동일 자산).

### 건드리지 않은 것 (중요)

`feedback()`/`assess()`/`advance()`와 `handle()`의 take/undo/submit/choose 분기는 **단 한 줄도** 바꾸지 않았다. 점수·독립수행 판정·힌트 로직·연속 학습(fading) 규칙은 전부 그대로다. 바뀐 것은 전환 화면(지도/이동 비트)을 기존 진입점(`showIntro`/`chapterEnd`/`demo`의 버튼 라우팅) 주변에 끼워 넣은 것뿐이다. Playwright로 3개 챕터 전체를 자동 플레이해 state 변화(`__moaMissionQA()`)를 읽어 검증했다 — qa/test-results.md 3차 업데이트 참고.

### 추가로 발견해 고친 것: berry 자산 누락

작업 중 `.food.berry`가 실제로 share/compare/make 전환(transfer)·연습(practice) 단계에서 광범위하게 쓰이는데도 1~2차에서 도토리(acorn)만 클레이로 바꾸고 berry는 기존 평면 CSS 그라디언트 그대로였다는 것을 발견했다. `berry_single.png`를 같은 스타일로 생성해 교체했다.
