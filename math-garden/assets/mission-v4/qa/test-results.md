# QA 결과 — mission-v4 1차 체크포인트 (2026-10-22)

범위: 공유(share) 미션의 "함께 연습"(guided) 화면 1개를 PC 1280px·태블릿 768px·모바일 390px에서 Playwright(로컬 서버, `math-garden/` 소스 그대로 서빙)로 실제 클릭해 검증. 사람이 직접 브라우저로 플레이하지는 않았다 — 아래 항목 중 "자동 브라우저 캡처"로 명시한 것은 Playwright 자동화 결과다.

## 요약

이번 체크포인트는 작업지시서가 1차로 요구한 "나무·도토리·바구니·곰" 네 가지를 중심으로 통과했지만, **접시·다른 동물·배경 통일·0~10 전체 수량·이동 애니메이션·사이트 전체 회귀 검사는 아직 완료되지 않았다.** 이 상태를 "완료"라고 보고하지 않고 다음 단계로 분리해 둔다.

## 2차 업데이트 (같은 날, 사용자 승인 후)

사용자가 1차 체크포인트를 승인하고 "나머지들 싹다 만들어, 학습지 말고 게임처럼 느껴지게"를 요청해 추가 작업함:

- 실제 코드가 쓰는 나머지 동물(토끼·여우·개구리·새) + 접시(plate) 전부 같은 클레이 스타일로 확장 — PC에서 각 동물별 화면 스크린샷 확인(previews/after_fox_friend.png, after_bird_friend.png).
- 클릭 피드백(눌림 반응), 등장 시 팝인 애니메이션, 가이드 곰/대기 친구의 미세한 흔들림, 성공·챕터완료 카드의 팝인, 챕터 완료 시 색종이(confetti) 축하 연출을 추가했다. **상태·점수·타이머 로직은 전혀 건드리지 않았고**, 기존 `prefers-reduced-motion` 전역 규칙이 새 애니메이션도 그대로 덮는다.
- 여전히 안 된 것: 배경(forest-world.svg) 재제작, 미구현 기능(다리·가게)용 소품, UI 단색 아이콘, 0~10 전체 수량 실측, 드래그 제스처. `asset-manifest.json`의 `notDone`에 그대로 기록되어 있다.

## 3차 업데이트 (같은 날, "학습지 같다" 지적 이후 — 구조 재설계)

사용자가 "길가다 나무발견하고 그런 스토리도없고... 학습지 풀듯 문제나오고"라고 직접 지적했고, AskUserQuestion으로 범위를 확인해 "전체 구조 재설계(오버월드/맵)"를 선택받았다. 작업 범위: (1) 숲속 지도(오버월드) 화면 신규 추가, (2) 챕터당 1회 "이동(travel)" 발견 비트 추가, (3) 배경 클레이 스타일 기본값 채택 결정, (4) berry 자산 누락 발견 및 보완, (5) 첫 화면 `.intro-bag` 바구니 비주얼 교체.

| 항목 | 결과 | 비고 |
|---|---|---|
| 오버월드 지도가 실제로 동작함(잠김→현재→완료 전환) | **통과(자동화 검증)** | Playwright로 `share→compare→make` 3개 챕터를 전부 자동 플레이(`__moaMissionQA()` state 판독 기반)하며 지도 노드 상태가 매번 정확히 전환되는 것을 확인(`previews/overworld_map_progress_mobile.png`, `overworld_map_complete_mobile.png`). 완료된 노드를 다시 클릭하면 해당 챕터가 재시작(시범부터)되는 것도 확인. |
| 이동(travel) 비트가 모든 챕터에서 뜸 | **통과** | share/compare/make 각 챕터 진입 시 시범 직후 1회씩 정상 표시됨을 자동 플레이 루프로 확인. 모바일·PC 스크린샷 모두 확보(`travel_beat_mobile.png`, `travel_beat_pc.png`). |
| 점수·판정 로직 무변경 | **통과** | `feedback`/`assess`/`advance`와 `handle()`의 take/undo/submit/choose 분기는 diff상 한 글자도 바뀌지 않았다. 기존에 있던 "5번째 스텝에서 조기 숙달 시 챕터 조기 종료" 로직도 자동 플레이 중 그대로 발동하는 것을 확인했다(의도된 기존 동작이지 이번 회차의 버그가 아님). |
| 콘솔/페이지 JS 에러 없음 | **통과** | 전체 3챕터 자동 플레이 + 지도/이동 화면 전환 전 구간에서 `pageerror` 0건. |
| PC 1280 / 태블릿 768 / 모바일 390에서 지도·이동 화면 레이아웃 | **통과** | PC·태블릿·모바일 전부 스크린샷 확인(`overworld_map_tablet.png`, `travel_beat_tablet.png` 포함), 깨짐·넘침 없음. |
| 배경(클레이 vs 기존 SVG) 비교 | **결정 완료** | 클레이 배경을 지도/이동/과제 화면 전부에 적용한 상태로 PC/모바일 스크린샷 확보. 전경과의 그림체 통일감이 확연히 좋아졌고, 우려했던 저해상도 흐림은 실제 화면에서는 크게 거슬리지 않아 기본값으로 채택했다. |
| berry 자산 누락 보완 | **통과** | `.food.berry`가 share/compare/make의 transfer·practice 단계에서 실제로 쓰이는데 1~2차에서 빠뜨렸던 것을 발견, 같은 클레이 스타일로 제작해 교체. 별도 스크린샷은 찍지 않았으나 CSS 적용 자체는 acorn과 동일한 검증된 패턴(`background-image`, `:before`/`:after` content:none)이라 구조적 리스크는 낮다. |
| 첫 화면(`intro-bag`) 바구니 비주얼 교체 | **통과** | `basket_empty.png` 배경으로 교체 후 모바일·PC 스크린샷으로 확인(`intro_bag_mobile.png`, `intro_bag_pc.png`) — 도토리·베리 칩이 바구니 손잡이 아래쪽에 자연스럽게 걸쳐 보인다. |
| 리듀스드 모션(`prefers-reduced-motion`) | **로직상 커버됨, 시각 재확인은 안 함** | 기존에 있던 전역 와일드카드 규칙(`*,*:before,*:after{animation:none!important}`)이 이번에 추가한 지도 펄스·발자국 점 애니메이션도 자동으로 덮는다(코드 확인). 실제로 모션 감소 모드를 켜고 스크린샷으로 재확인하지는 않았다. |

### 요약

구조 재설계(지도+이동 비트)는 핵심 흐름(3챕터 전체, PC·태블릿·모바일)에서 정상 동작하고 에러 없음을 자동화로 확인했다. **여전히 못한 것: berry 자산의 스크린샷 미확보(코드 패턴은 acorn과 동일해 리스크는 낮음), 리듀스드모션 시각 재확인(코드상 커버는 확인), 0~10 전체 수량 실측, 사이트 전체 회귀(15종 허브 등) 재확인.** 이 상태를 "완료"로 보고하지 않는다.

## 4차 업데이트 (같은 날 — "글 최소화, 글 못 읽는 아이도 참여" 지시)

사용자 지시: "글은 최소화하고... 어린아이들도 글없고 글못읽어도 잘 참여하고 알아서 게임 다하잖아 그전략으로 해봐." 핵심 조작 흐름(시작·제출·이동·재도전·지도복귀·계속하기)을 **읽지 않고도** 끝까지 할 수 있게 만드는 작업.

| 항목 | 결과 | 비고 |
|---|---|---|
| 핵심 액션 버튼이 아이콘 전용으로 바뀜 | **통과** | start(▶)/submit(✓)/arrive(→)/advance(→)/repeat(↻)/next-chapter(지도 아이콘) 전부 인라인 SVG 아이콘으로 교체. 기존 한글 텍스트는 삭제하지 않고 `sr-only`(화면에는 안 보이고 스크린리더만 읽는) 클래스로 DOM에 유지 — 시각 장애가 있는 성인 보호자가 스크린리더로 쓸 때는 오히려 기존과 동일하게 안내 문구를 듣는다. |
| 헤더/하단 버튼(소리·새모험·힌트·다른 놀이)도 아이콘화 | **통과** | 스피커/집/전구/셔플 아이콘으로 교체, `aria-label`과 `sr-only` 텍스트는 유지. 소리 켜짐/꺼짐 토글 시 아이콘 자체가 스피커 on/off 모양으로 바뀜(텍스트 토글 로직을 아이콘 토글로 대체). |
| 정답/오답을 텍스트 없이도 알 수 있음 | **통과(신규 기능)** | `feedback()`에 `flashFeedback()` 훅을 추가해 제출 직후 화면 중앙에 큰 초록 체크(정답)/빨강 엑스(오답) 아이콘이 0.65초간 팝업된다. 기존 효과음(`sfx`)·상태 문구는 그대로 유지하고 있어 "아이콘+소리+글" 3중 신호가 된다 — 통과이지만 1회성 애니메이션이라 색맹(적록색약) 사용자 고려는 아이콘 모양(체크 vs 엑스) 자체가 이미 구분을 담당하므로 색상에만 의존하지 않는다. |
| 점수·판정 로직 무변경 | **통과** | `feedback()`에 추가된 줄은 맨 앞의 `flashFeedback(isCorrect);` 한 줄뿐이고, 그 아래 기존 조건문·`assess()`·`advance()`·`handle()`의 take/undo/submit/choose 분기는 diff상 무변경. |
| 버튼이 시각적으로도 "눌러야 할 것처럼" 보임 | **통과(기존 결함도 같이 고침)** | 점검 중 발견: 교체 전에도 start/arrive/advance 버튼은 사실 투명 `.interaction` 스타일이라 배경·테두리 없이 글자만 떠 있는 상태였다(이번 작업과 무관한 기존 결함). 이번에 원형 오렌지 버튼 스타일을 추가해 아이콘이 명확한 버튼처럼 보이도록 같이 고쳤다. |
| 자동 플레이 전체 회귀 | **통과** | Playwright로 intro→map→demo→travel→task(오답 1회+정답)→success→chapterEnd까지 전 구간 스크린샷 확인, 콘솔/페이지 에러 0건. |

### 여전히 안 한 것 (정직하게)

- **설명 문장 자체(지시문·상태 메시지·챕터 요약 문단)는 삭제하지 않았다.** "최소화"를 "화면에서 안 보이게"가 아니라 "읽지 않아도 진행 가능하게"로 해석했다 — 텍스트는 보호자/더 큰 아이를 위해 화면에 남아 있고, 핵심 조작(버튼)만 아이콘으로 바꿨다. 지시문 폰트를 더 작게 줄이거나 완전히 숨기는 건 하지 않았다.
- 지도 노드(`map-node`)의 "첫 번째 숲길" 같은 캡션 텍스트는 그대로 남아 있다 — 아이콘(나무/갈림길/꽃)이 이미 주된 식별 수단이라 우선순위가 낮다고 판단해 남겨둠.
- quest-chip의 "함께 연습"/"혼자 해보기" 같은 단계명 라벨도 아직 텍스트 그대로.
- 숫자 진행 점(1·2·3)은 숫자 그대로 유지 — 유아도 비교적 일찍 익히는 상징이라 우선순위 낮음으로 판단, 바꾸지 않음.
- 컬러만으로 정답/오답을 구분하지 않도록 아이콘 모양(체크/엑스)을 다르게 했지만, 실제 색약 시뮬레이션으로 재검증하지는 않았다.



## 5차 업데이트 (같은 날 — 동시 작업 충돌 발견 + 선별 반영)

세션 중 사용자가 "ABA 기반 기초수학" 참고자료 + 매우 상세한 인수인계 문서를 전달했고, 이를 처리하기 전 요청대로 GitHub `main`/기존 PR을 먼저 확인했다. 그 결과 **다른 AI 작업자(ChatGPT Codex Connector)가 동일한 `mission.js`/`mission.html`을 동시에 수정 중인 열린 draft PR #400**을 발견 — 시범(demo) 단계 삭제, 시작/계속 버튼 제거, 성공 후 타이머 자동 진행이라는 상반된 설계 방향이었다. 사용자에게 보고하고 방향을 물은 결과: **"내 방향(지도+이동비트+시범 유지) 유지, Codex PR에서 배울 것만 선별 반영"**으로 결정됨.

PR #400에서 가져온 것:

| 항목 | 결과 | 비고 |
|---|---|---|
| 공유(share) 개념: 바구니→친구 직접 탭으로 먹이기 | **통과** | 추상적인 "배달하기" 버튼 대신 각 친구를 직접 눌러 간식을 주는 방식으로 교체 — 일대일 대응을 더 구체적·물리적으로 조작하게 함. 접시에 담긴 그림이 실제로 채워지는 게 보임. 자동화 테스트로 "빈 바구니로 친구 누르면 아무 일도 안 일어남 + 나무 쪽에 황금색 테두리로 유도" 확인. |

- **성공/챕터종료 후 타이머 자동 진행(1.8초/2.5초)** — 채택 안 함. 사용자 문서 6절 "실수하거나 느리게 반응해도 불필요하게 불안하거나 좌절하지 않는가?"와 직접 배치된다고 판단 — 타이머가 아이를 기다려주지 않고 강제로 넘어가는 것은 시간 압박이 될 수 있음. 아이콘 버튼을 눌러야 다음으로 넘어가는 기존 방식 유지.
