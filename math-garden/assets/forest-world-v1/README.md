# 숲 세계 (forest-world-v1) — 숲 마을 + 숲길 모험 융합

사용자가 숲 마을(village.html)과 도토리 배달 모험(mission.html) 중 뭐가 더 나은지 묻고, "융합 안 돼?"라고 제안 → Claude가 "숲 마을을 지속되는 세계로 두고, 각 수학 개념을 그 세계 안의 퀘스트 장소로 만들자. 퀘스트를 깨면 반려동물 먹이고 마을 지을 자원을 번다"는 구체적 융합안을 제안했고, 사용자가 "해 그럼"으로 승인해 제작.

## 핵심 아이디어

**학습이 재밌는 걸 얻는 방법이 되게 한다.** 숲길 모험(share/compare/make 세 개념, mission.js의 교수 구조 그대로)을 깨면 도토리·딸기를 보상으로 받고, 그 자원으로 반려동물을 먹이고 마을을 짓는다. "학습을 해야 재밌는 걸 할 수 있다"가 아니라 "학습 자체가 재밌는 걸 얻는 길"이 되도록 했다.

## 네 개 탭, 하나의 세계

모으기 / 숲길 모험 / 반려동물 / 짓기 — 네 탭을 순서 없이 자유롭게 오간다. 자원 칩(도토리·딸기 개수)은 네 탭 전부에서 항상 보여서, 모험을 깨는 것과 자원이 느는 것의 연결이 눈에 보인다.

## 건드리지 않은 것 (중요)

`math-garden/mission.html`/`mission.js`/`mission.css`와 `math-garden/village.html`/`village.js`/`village.css`는 **전혀 수정하지 않았다** — 둘 다 독립 페이지로 그대로 남아있고 각자 정상 동작한다(diff로 확인, Playwright로 재검증). 이 융합은 완전히 새로운 파일(`forest-world.html`/`.js`/`.css`) 세 개로만 만들었고, 두 기존 파일에서 로직을 **이식(port)**했다 — 특히 mission.js의 점수·독립수행 판정 로직(`feedback`/`assess`/`advance`)은 한 글자도 바꾸지 않고 그대로 옮겼다.

## 새로 생긴 연결점 (딱 하나)

`chapterEnd()`에서 숲길을 하나 깨면 **고정 보상**(도토리 +3, 딸기 +2)을 준다. 성과(도움 없이 풀었는지, 몇 번 틀렸는지)에 따라 보상을 다르게 주지 않는다 — 보상을 성적에 비례시키면 보상이 암묵적 처벌 신호가 되어, 이 프로젝트 전체의 "벌점 없음" 원칙과 충돌하기 때문이다. 보상 액수(+3/+2) 자체는 연구에서 도출된 값이 아니라 균형을 위한 임의 설정이다.

## 포함된 것

- `forest-world.html`/`.js`/`.css` (새 경로: `math-garden/` 바로 아래, mission/village와 같은 위치)
- 새 이미지 자산 없음 — `mission-v4/`와 `village-v1/`의 기존 자산만 재사용
- `style-guide.md`, `asset-manifest.json`, `qa/test-results.md`, `previews/`

## 점검 중 발견한 기존 버그 (mission.css)

`mission.css`의 `#sound,#restart,#help,#change{display:inline-flex}` 규칙(4차 아이콘화 작업 때 추가)이 `[hidden]` 속성보다 CSS 명시도가 높아서, 지도 화면에서도 `#help`/`#change` 버튼이 숨겨지지 않고 보이는 버그를 이 작업 중 발견했다. **라이브 mission.html에서도 재현 확인**(Playwright로 `.isVisible()` 체크). `forest-world.css`에는 `#help[hidden],#change[hidden]{display:none!important}`로 로컬 수정했고, 이후 **mission.css 자체도 같은 방식으로 수정되어 커밋됨**(세션 내 별도 커밋) — 더 이상 라이브 mission.html에도 남아있지 않다.

## 2차 업데이트 — 모험 B: 끊어진 다리 복구 (같은 세션, 사용자 "링크걸고만들어" 지시)

사용자가 15종 허브에 이 페이지를 링크하고(완료, 별도 커밋) B~E 모험 콘텐츠를 계속 만들라고 지시 → `LEARNING-DESIGN.md`가 이미 다음 과제로 명시해둔 "다리 복구(합치기·길이)"를 네 번째 퀘스트 개념으로 추가했다.

### 왜 이 개념인가

기존 `make`(빈자리 채우기)는 정답이 항상 하나뿐이다(목표 수량까지 단위 1개씩 채우기). 다리 복구는 **같은 목표 길이를 여러 다른 조합으로 만들 수 있다**는 걸 가르친다 — 길이가 다른 나무 판자 여러 개 중에서, 합이 목표 길이와 정확히 같아지는 조합이면 무엇이든 정답이다(5=2+3도 맞고 4+1도 맞음). 정답 판정은 `state.planksPlaced`에 실제로 놓인 조각들의 합을 그때그때 계산하는 방식이라, 하드코딩된 "하나의 정답"이 없다.

### 구현

- `templates.bridge`에 demo→guided→probe×2→transfer→practice→transfer 7개 항목(기존 3개 개념과 동일한 구조). guided는 단일 경로, 나머지는 의도적으로 여러 유효 조합이 존재하도록 설계(자동화 테스트로 "의도된 정답과 다른 조합"으로도 성공하는 것을 확인).
- 판자를 과하게 놓아 목표를 넘기면(overshoot) 실패 처리하지 않고 그대로 둔다 — 판자를 다시 빼서(undo) 고칠 수 있고, 이렇게 **넘쳤다가 스스로 고친 경우는 "독립 성공(clean)"으로 집계하지 않는다**(share 개념의 과다수집 로직과 동일 원칙, 자동화 테스트로 확인).
- 소재 전환(transfer 단계)은 새 이미지를 만드는 대신 CSS 필터(`sepia`+`hue-rotate`)로 같은 판자 이미지를 이끼 낀 색조로 바꿔 재사용했다.
- 길이 차이는 판자 너비(CSS 클래스 `plank-1`~`plank-4`)로만 표현 — 숫자를 읽지 않아도 눈으로 비교 가능.
- 시각적 명료성 문제를 점검 중 발견·수정: 처음에는 다리 그림 위에 판자를 겹쳐 그렸는데 배경 그림(돌기둥·개울)과 섞여 잘 안 보였다. 장식용 다리 아이콘과 "놓은 판자" 상자(연두 테두리)를 분리해 명확하게 고쳤다 — `previews/bridge-overshoot.png` 전/후 비교 가능.
- 지도에 4번째 노드 추가(`CONCEPTS`/`templates`/`MAP_ICONS`/`TRAVEL_LINES` 배열에 항목 추가만으로 끝 — 지도·잠금해제·보상 로직에 하드코딩된 "3개"가 없는 것을 먼저 확인했다).
- 완료 보상은 기존과 동일하게 고정 +3 도토리/+2 딸기.

### 새 자산 (Canva 예외 승인 범위 내, mission-v4/style-guide.md 템플릿 그대로 사용)

- `objects/bridge_gap.png` — 끊어진 다리 디오라마(지도 아이콘 + 이동 장면 + 과제 화면 장식 겸용, 3중 재사용)
- `objects/wood_plank.png` — 나무 판자 1개(CSS 너비로 길이 1~4 표현, 소재 변형은 CSS 필터로)

### 건드리지 않은 것 (재확인)

`feedback()`/`assess()`/`advance()`의 기존 share/compare/make 분기와 점수 로직은 한 글자도 안 바꿨다 — 새 `bridge` 분기만 추가. 4개 개념 전체 자동 플레이로 재검증.

## 3차 업데이트 — 연령대별 반응 예측 (실제 아동 검증 아님)

사용자가 "다양한 연령 아이들 반응 예측해보고 보완점 수정 추가"를 요청 → 4개 연령대(만 4세 전후/5~6세/7~8세/발달지연·주의집중 어려움)별로 각 화면에서 예상되는 혼란·지루함·답답함·선호도를 추론해 `AGE-BAND-REACTION-PREDICTIONS.md`에 정리했다. **이번 라운드는 코드 변경 없음** — 확신 있게 "안전하고 명백히 좋다"고 판단할 항목을 찾지 못해, 추측만으로 코드를 고치기보다 권고사항으로 남기는 쪽을 택했다. 발견한 주요 지점: 7~8세에게는 반려동물 성장(2단계 상한)·건물 종류(3종)가 금방 바닥날 수 있음, 발달지연 아동에게는 과제 중간 미저장 제약이 다른 연령대보다 더 크게 작용할 수 있음. 상세 내용과 전체 권고사항은 해당 문서 참고.

## 공개 배포 안 함

이 브랜치는 main에 병합하지 않았고 GitHub Pages에도 반영되지 않았다. `index.html`(15종 허브)의 기본 진입점은 이 페이지로 연결해 두었다(별도 커밋, 사용자 지시) — 단, 이것은 브랜치 내부 변경이며 main에 병합·배포되기 전까지는 공개 홈페이지에 반영되지 않는다. 모험 C(여우네 가게)/D(변신하는 숫자 숲)/E(새 마을 탐험)는 아직 미구현.

## 4차 업데이트 — 연령대별 권고사항 4건 실행 ("알아서 다해 싹다해")

- 반려동물 3단계 성장(20회 먹이기) + 건물 2종 추가(다리 장식·오솔길 표지판, 기존 자산 재사용, 새 생성 없음) — 7~8세 콘텐츠 상한 문제 대응.
- 과제 중간 상태(진행 중인 step/선택/제출 내역)를 localStorage에 저장하도록 확장 — 새로고침이나 탭 전환 후에도 같은 자리에서 이어서 할 수 있음(이전엔 항상 그 챕터 시범부터 다시 봐야 했음). 점수·판정 로직은 무변경.
- 비교 개념 무글자 힌트는 유지로 결정(코드 변경 없음, 결정만 기록).
- 다리 콘텐츠 7개 전수 점검 — 조각 수·목표값 모두 기존 상한 안에 있어 변경 불필요.
