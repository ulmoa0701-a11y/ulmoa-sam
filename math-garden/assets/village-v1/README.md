# 숲 마을 (village-v1) — 자유 놀이 프로토타입

작업지시서: 도토리 배달 대작전(mission.html) 작업과 같은 흐름에서, 사용자가 "교육용 연습도구는 이미 많다 / 진짜 게임 그 자체를 해보자, 이 게임하면 알아서 교육에 도움도 되고" 라고 명시적으로 요청해 별도 프로토타입으로 제작.

## 핵심 설계 원칙

- **강제 순서 없음**: 모으기/반려동물/짓기 세 탭을 아무 때나 자유롭게 오가며 플레이. "1단계부터 7단계까지" 같은 진행바가 없다.
- **정답/오답 게이트 없음**: 먹이를 주거나 건물을 지을 때 "틀렸다"는 평가가 없다. 자원이 부족하면 그냥 아직 못 할 뿐 — 벌칙이나 교정 문구 없이 살짝 흔들리는 피드백만 준다.
- **글 없이 조작 가능**: 모든 액션(모으기/먹이주기/짓기/탭 전환/소리)이 아이콘·이미지 버튼이다. 숫자(자원 개수)만 예외 — 셀 수 있는 양을 보여주는 가장 명확한 방법이라 남겨뒀다.
- **모으는 재미**: 지은 건물이 마을 땅에 계속 쌓여 보인다(챕터 끝나면 사라지는 이전 미션 방식과 다름). 반려동물도 먹이를 줄수록 성장 단계가 바뀌고 그 모습이 유지된다.

## 범위 — 이번에 한 것 / 안 한 것

**했다:**
- 모으기: 나무 클릭 → 도토리 +1, 딸기 클릭 → 딸기 +1. 제한 없이 반복 가능.
- 반려동물(곰 재사용): 도토리/딸기로 먹이주기 → 허기 게이지(발바닥 5칸, 숫자 아님) 상승 + 일시적으로 행복한 표정. 먹인 횟수 누적(5회/12회)에 따라 크기가 커지고 12회부터는 꽃 왕관이 추가되는 2단계 성장.
- 짓기: 꽃밭(도토리 2)/바구니 장식(도토리 3)/오두막(도토리 5+딸기 2) 세 가지를 모아둔 자원으로 짓고, 지은 건물은 마을 땅에 계속 쌓인다. 못 지으면 버튼이 흐려 보이고 탭하면 살짝 흔들릴 뿐 에러 문구 없음.
- 저장: `localStorage`(`moa-village-pilot-v1`)에 자원/허기/먹인 횟수/지은 건물 전부 저장 — 새로고침해도 유지.

**안 했다 (정직하게):**
- **한글(자음·모음·띄어쓰기) 콘텐츠는 이번 라운드에 넣지 않았다.** 사용자가 대화 중 언급했지만 "같은 게임에 수학과 한글을 함께 넣을지"를 확정 답받지 못했고, 범위를 한정하지 않으면 품질이 떨어질 위험이 있어 **이번은 수학(수량)만**으로 한정했다 — 한글은 같은 메커닉(모으기/키우기/짓기)으로 별도 게임을 만드는 걸 다음 단계로 제안한다.
- 반려동물 종류 선택(지금은 곰 하나 고정), 건물 종류 다양화(지금 3종), 마을 땅 배치 자유도(드래그 없이 자동 정렬), 사운드 디자인(기존 mission.js와 같은 단순 비프음 재사용, 새로 만들지 않음) — 전부 v2 후보로 남겨둠.
- 다중 저장 슬롯·클라우드 동기화 없음(기존 mission.js와 동일하게 기기 로컬 저장만).

## 연동/비간섭

- `math-garden/mission.html`/`mission.js`/`mission.css`는 **전혀 건드리지 않았다** — 별도 파일(`village.html`/`village.js`/`village.css`)로 완전히 분리. Playwright로 mission.html이 여전히 정상 동작(오버월드 지도까지)하는 것을 재확인했다.
- 신규 자산은 전부 `math-garden/assets/village-v1/` 밑에만 추가했고, 기존 `mission-v4/` 자산(나무·바구니·도토리·딸기·곰·꽃)은 재사용만 했지 수정하지 않았다.
- Canva 생성은 `mission-v4/style-guide.md`에 기록된 "이번 math-garden 작업에 한정된 예외 승인"의 연장선으로, 오두막(cottage) 자산 1개만 새로 생성했다. 저장소 기본 Canva 금지 규칙은 그대로다.

## 공개 배포 안 함

이 브랜치는 main에 병합하지 않았고 GitHub Pages에도 반영되지 않았다. `index.html`(15종 허브)에 링크도 아직 추가하지 않았다 — 사용자가 방향을 확인한 뒤 연결할지 결정한다.
